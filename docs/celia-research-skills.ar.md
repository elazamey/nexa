# مكتبة Celia للأبحاث والمهارات الاستشارية

**20 سبتمبر 2026 — إضافة مستقلة اختارها المستخدم، وليست P01 أو إصلاحًا لـH2/H3.**

أضيفت **10 مراجع و10 بطاقات مهارات** داخل الشريحة الاستشارية. الوظيفة المنفذة هي: تصفح بيانات موثقة، واختيار قوائم مراجعة بقواعد محددة، وربطها بالتقرير الموقّع. **ليست** تنزيل أوراق كاملة أو تدريب نموذج أو تنفيذ خوارزميات الأبحاث أو مهارات قادرة على تشغيل أوامر.

## التشغيل

```bash
node tools/celia-system.mjs library
node tools/celia-system.mjs skills
node tools/celia-system.mjs skills --id SK07
node tools/celia-system.mjs status
node tools/celia-system.mjs advise --input /path/to/request.json
```

`library` و`skills` يعملان دون شبكة أو نموذج أو مجموعة بيانات. `advise` يضيف `payload.knowledge`، ويضم ختم التقرير هذا الحقل. تغييره أو تعديل رابط مرجع أو بطاقة بعد التوقيع يفسد التحقق. صلاحيات العمليات الخمس المحلية السابقة لم تتوسع ولم نختلق TOOL_RESULT للبطاقات؛ توليد الإرشاد دالة محلية إضافية، وليس استدعاء أداة تنفيذية.

لكل بطاقة اسم وإجراءات مراجعة وأدلة مطلوبة وحدود وروابط أبحاث وIDs من الكتالوج. `GUIDANCE_ONLY` لا يعني أن التقنية المقابلة أصبحت منفذة. تبقى حالات اتصال الـ200 كما كانت: 25 محدودة، 3 شرطية، 8 محظورة، و164 غير موصولة.

## لماذا هذه المراجع؟

الاختيار تحريري بحسب احتياجات NEXA الحالية: أدلة الإصلاح، حدود الأدوات، نقد الفشل، البيانات والتقييم، ثم تمييز ضمانات الاستمرارية. هذه مراجع تأسيسية منتقاة **وليست مسحًا شاملًا أو ادعاء بأنها أحدث أبحاث 2026**.

تمت مراجعة ملخصات وmetadata الصفحات الأصلية أدناه، لا النص الكامل أو إعادة التجارب. روابط arXiv مثبتة بالإصدار الذي عرضته الصفحة أثناء المراجعة. بيانات المؤشرات والأداء المنشورة في الأوراق لم تُنقل كأداء لـNEXA. الملخصات العربية وقوائم المراجعة صياغة محلية؛ توصياتنا الهندسية ليست نتائج بحثية أثبتتها كل ورقة حرفيًا.

## كيف يختار النظام البطاقة؟

- SK01/SK02/SK03: مراجعة الدليل والخطة ومصدر البيانات لكل مرشح؛ غياب التقرير لا يتحول إلى PASS.
- SK04: إذا أفاد التقرير بفشل/skip/todo/cancel أو اختلف العدد أو exitCode.
- SK05: إذا صرّحت الخطة بتغيير ملفات اختبار.
- SK06: إذا صرّحت الخطة بتغيير أمني أو اعتماديات؛ ليست فحص ثغرات أو SBOM.
- SK07: عند التصريح بمساس حد أمني، **للنظر في ضمانات الاستمرارية إذا كانت مرتبطة بالتغيير**، وليس تشخيصًا تلقائيًا لعيب filesystem.
- SK08: توثيق البيانات، مع تمييز عدم الاتصال من تقديم بيانات مراجَعة صراحةً.
- SK09: عند تقديم artifact نموذج صالح صراحةً إلى `advise`؛ لا يشهد ذلك بمصدر تدريبه.
- SK10: التذكير بالامتناع عند غياب النموذج، أو بعدم معايرة درجة المرشح إن وجد.

التحديد بقواعد على الخصائص المصرّح بها وملخص TAP، **لا semantic search أو LLM ولا تحليل diff فعلي**. نص الهدف لا يستطيع إدخال أوامر أو تغيير طريقة الاختيار. الـchecklist إجراء مراجعة مقترح، وليس مهارة اجتازها النظام أو سجل إجراءات نفّذها.

`researchIds` في خطة المستخدم تظل بعقد المتعلّم السابق. إذا طابقت معرفًا موجودًا بلا إصدار، يُعلن الإصدار المراجع الذي رُبط به. إذا طلب المستخدم إصدارًا آخر غير مراجع، أو معرفًا غير موجود، يظهر في `unresolvedResearchIds` ولا يُجلب تلقائيًا ولا يستبدل خفية. الاستشهاد ليس تأييدًا لصحة الخطة. لا رفع درجات نموذج بسبب اسم الورقة أو عدد المراجع.

## حقول الثقة والحدود

- `libraryHash`: SHA-256 canonical للمكتبة كاملة وإصدارها؛ تتغير مع محتواها. هذه بصمة الملخصات والبطاقات المحلية، **ليست** بصمة PDF أو توقيع الناشر.
- `reviewScope`: ملخص وmetadata فقط؛ نجاح جلب الصفحة عبر أداة التصفح أثناء الإعداد لا يثبت اتصال موصل `research` الحي في بيئة التشغيل.
- `algorithmImplementedByThisLibrary: false` لكل ورقة. لم تُشغّل SWE-bench/AgentDojo، ولم تُطبّق Reflexion/Self-Refine أو المعايرة أو ALICE/BOB بهذه الإضافة.
- `executionAllowed: false`, `automaticIngestion: false`, `automaticTraining: false`, `authority: none`؛ لا منح capabilities أو تدريب أو تفعيل نموذج من المراجع.
- `recommendSkills` API يستقبل سياقًا منطقيًا من مستدعيه عن وجود نموذج/بيانات، ويصفه بأنه caller-supplied لا attestation. في `advise` يُبنى السياق من المدخلات التي تحققت منها الشريحة الحالية.
- metadata والعناوين والروابط للقراءة فقط. لا تنزيل code/PDF، ولا parsing لمحتوى خارجي أثناء النصيحة، ولا تحميل plugin من URL.
- أي تنفيذ لاحق لخوارزمية يحتاج حزمة مستقلة واختبارًا مستقلًا وحقوق بيانات وميزانية وعزلًا مناسبًا؛ وجود بطاقة لا يفتح أي بوابة.

## الأدلة والاختبارات — لقطة جديدة مستقلة

| الجولة المنفذة | النتيجة |
|---|---|
| المكتبة الجديدة + النظام + المتعلّم | **52/52**، منها 13 اختبارًا جديدًا |
| انحدار حدود الأمان السابق | **59/59** |
| `npm run verify` | **428 اختبارًا: 426 PASS / 2 KNOWN FAIL**، exit 1 |

الفشلان هما H2 وH3 الأصليان. لا skip/cancel/todo في هذه الجولات؛ مراحل verify التالية لفشل npm test لم تصل إليها الجولة. الـ52 والـ59 ضمن المجموعة الشاملة؛ لا تجمع الأعداد كاختبارات مستقلة إضافية. هذه الشريحة اجتازت فحوصها الحالية، لا النظام كله.

الاختبارات الجديدة تفحص المراجع/الإصدارات وربط البطاقات، ثبات النسخة الداخلية عند تعديل مخرجات القارئ، حالات الفشل والغياب والامتناع، عدم جلب مصادر مجهولة، رفض المدخلات غير الصالحة، سلامة ختم التقرير عند التلاعب بالبطاقات، وعدم ترقية حالات الكتالوج. أمر المكتبة يعمل تحت Node Permission دون منح كتابة أو child processes. هذه ليست اختبارات هروب sandbox شامل أو تشغيل benchmarks الأبحاث.

## الملفات والتراجع

- `system/src/library-data.js`: المراجع وبطاقات المهارات المراجَعة، مجمدة داخليًا.
- `system/src/library.js`: تصفح واختيار حتمي محدود؛ لا I/O.
- ربط محدود في `system.js`, `catalog.js`, `index.js` وCLI؛ اختبار جديد مستقل دون تغيير الاختبارات السابقة أو أدوات حدود COMMIT.
- لا dependencies جديدة. لا تغيير أوزان أو بيانات مستخدم أو wire schema للنواة.
- التراجع عن هذه الإضافة يزيل حقل knowledge وأوامر المكتبة وربط حالتها وملفاتها الجديدة فقط، دون المساس بالعمل السابق أو بيانات السلطة. لا reset للفرع أو استعادة عمياء من أرشيف قديم.

لم يحدث commit/push/merge/deploy، ولم تبدأ حزمة إصلاح H2 أو H3.
