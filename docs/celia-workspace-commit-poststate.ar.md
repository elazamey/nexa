# حزمة P02.x — التحقق البعدي من الحالة (Post-State Verification)

**21 سبتمبر 2026 — الفرع `arena/01a0c63f-nexa`، Node v22.22.3. القرار العام: HOLD.**

## 1. الفجوة

كان `createWorkspaceCommitter` يُرجع:

```js
writeFileSync(target, file.content, ...);
return { ok: true, changedFiles: changed.length, ... };
```

أي أن `ok: true` كانت مبنية على **أن استدعاء النظام لم يرمِ استثناءً**. وهذا ليس إثباتًا أن الأثر المقصود موجود على القرص:

```
execution succeeded  ≠  effect verified
```

الحالات التي تفلت: filesystem يُبلغ نجاحًا دون كتابة كاملة، اقتطاع لاحق، أو أي تعديل بعد عودة الاستدعاء. هذا يخالف مبدأ NEXA الأساسي: **الوكيل يدّعي، والنظام يُثبت**.

## 2. العقد الجديد

```
WRITE
  ↓
READ BACK (من القرص، لا من الذاكرة)
  ↓
COMPARE bytes
  ├── MATCH    → ok:true + postState
  └── MISMATCH
        ↓
      RESTORE
        ↓
      RE-READ الاستعادة
        ├── مُثبتة   → 503 COMMIT_EFFECT_UNVERIFIED
        └── غير مُثبتة → 503 COMMIT_RECOVERY_UNVERIFIED + قفل الجذر
```

النقطة التي أضافها المراجع وكانت ضرورية: **`restore()` نفسها نجاح غير مُثبت** حتى تُعاد قراءتها. لذلك لا نسجّل «استُعيد» إلا بعد إثباته، ويُفصل رمزا الخطأ.

### ما أضيف في الشفرة

- `verifyPostState(base, applied)` — يعيد قراءة كل هدف مكتوب ويقارن الحجم ثم البايتات بالمحتوى المتحقق منه، عبر `regularFile` (فيعيد فحص symlink/nlink أيضًا).
- `verifyRestored(base, attempted)` — يثبت الاستعادة. `restore()` كان يتحقق من بايتات ووضع الملفات الموجودة، لكن **مسار الحذف كان يمضي بلا إثبات**؛ الآن يُثبت اختفاء الملف المُنشأ (`STILL_PRESENT`).
- حقل `postState: { verified, method: 'READ_BACK_SHA256_EQUAL_BYTES' }` في الإرجاع الناجح.

**القفل انتقائي:** يُقفل الجذر فقط عند `RECOVERY_UNVERIFIED`. الاستعادة المُثبتة تترك جذرًا متسقًا، فلا مبرر لحجب كل طلب لاحق بـ503 شامل.

## 4. ما لا تدّعيه هذه الحزمة

هذا **Post-State Verification** وليس **Independent Verification**. التسمية الأدق مقصودة:

1. **ليس تحققًا مستقلًا.** القارئ هو نفس العملية المنفِّذة. الاستقلال الحقيقي يتطلب مراقبًا خارج مسار التنفيذ (inotify/auditd)، وهو غير موجود.
2. **لا يكشف A → B → A.** طفرة تحدث ثم تُعكس قبل لحظة القراءة تمرّ دون أثر.
3. **لا يحمي من كاتب خارجي يصل بعد نقطة القراءة.** ذلك حدّ H3 وقد ضاق ولم يُعدم.
4. **ليس crash consistency.** الانقطاع في منتصف الـcommit لا يعالجه هذا إطلاقًا — وهو **P03**، المانع المسجّل `P03_CRASH_RECOVERY_UNRESOLVED`.

## 5. قرار معماري: ما رُفض عمدًا

من المقترح الأوسع (MutationGuard، 17 حالة، Execution Attestation، Reconciliation، `packages/mutation/*.ts`) **لم يُنفَّذ شيء**، وذلك مقصود:

- المستودع **صفر TypeScript وصفر اعتماديات runtime**؛ إدخال TS يكسر ثابتًا معماريًا قائمًا.
- التصديق على تنفيذ لا يصمد أمام الانقطاع يوثّق وعدًا لا واقعًا.

الترتيب الملزم: **أثبت الـcommit primitive ← ثم دلالات التعافي ← ثم دلالات الطفرة ← ثم التصديق.**
