## §1 — الغرض والنطاق

يرسم هذا العقد حدود المسؤوليات بين أربعة أصناف مكوّنات في خط الأنابيب الأمني:

1. **الكواشف (Detectors)** — تنتج findings من فحص surface/كود.
2. **قارئ الـ Artifact (ArtifactReader)** — يقرأ ويتحقق من دليل إعادة الإنتاج المرفق بالـ finding.
3. **مُقيّم البوابات (SevenGateValidator)** — يحكم على الـ finding عبر البوابات السبع.
4. **جسر الشهادة (NexaEvidenceBridge)** — يوقّع إيصالات Ed25519 للنتائج المعتمدة فقط.

الغاية: **فصل من يُنتج الدليل عن من يتحقق منه عن من يوقّعه** — بحيث لا يصدّق أي مكوّن
نفسه، ولا يمر finding إلى التوقيع إلا بدليل قُرئ وتحقق منه مكوّن مستقل (استقلالية الكواشف:
`docs/Detector_Independence_Assertions.md`).

## §2 — تعريفات

| المصطلح | التعريف |
|:---|:---|
| **Finding** | نتيجة كاشف: كائن يحمل عنوانًا وشدة (`severity`) ومصدرًا و`artifact` اختياريًا |
| **Artifact** | دليل إعادة الإنتاج المرفق بالـ finding (انظر §3) — منتج الكاشف، لا حكم الكاشف |
| **Receipt** | إيصال موقّع Ed25519 يصدره الجسر عن finding معتمد فقط |
| **Rejection** | رفض صريح معلَّل `{ certified: false, ... }` — ليس إيصالًا ولا يحمل توقيعًا |
| **البوابات السبع** | مساند GATE_1..GATE_7 في `SevenGateValidator.evaluateFinding` |

## §3 — نموذج الـ Artifact

كل artifact كائن بالحقول:

```js
{
  kind: 'pattern-trace' | 'request' | 'response' | 'ast-trace' | 'content-match' | 'steps',
  locator: string,        // غير فارغ: 'endpoint:/path' | 'file:line' | 'parameter:name' | ...
  evidence: string | object,  // غير فارغ: الدليل الملموس نفسه (لا وصف له)
  producedBy: string      // هوية الكاشف المنتج، مثل 'VulnEngine.detectIdor'
}
```

قواعد:
1. الحقول الأربعة إلزامية، بأنواعها المذكورة.
2. `evidence` إن كان كائنًا فيجب أن يحوي بيانات فعلية (مفتاحًا واحدًا على الأقل).
3. **يُمنع أي حقل حكم ذاتي** (مثل `verdict`, `selfValidated`, `passed`) — حضوره رفضٌ
   فوري (AR-E06): الصلاحية تُستنبط من البنية فقط.
4. الـ artifact مادة خام للقراءة؛ لا يُقبل «artifact مُصدَّق مسبقًا» من أي طرف.

## §4 — واجهة القارئ

```js
class ArtifactReader {
  validate(artifact) → { valid: boolean, reasons: [{ code, message }], artifact?: <منقّح> }
}
```

1. القارئ لا يحتفظ بحالة بين الاستدعاءات (stateless) — نتيجة `validate` دالة في مدخله فقط.
2. القارئ لا يستدعي كواشف ولا بوابات ولا الجسر (§7).
3. أي خلل بنية يعيد `{ valid: false, reasons: [...] }` — القارئ لا يرمي استثناءات للبنية
   المعطوبة، ويبتلع الاستثناءات غير المتوقعة داخل رفض معلَّل (AR-E00) — **لا يُرجع valid:true
   عند الشك أبدًا** (§10.9).

## §5 — تكامل البوابات

### §5.1 — بوابة إعادة الإنتاج (GATE_2_REPRODUCIBILITY)

1. شرط المرور **الحصري**: `ArtifactReader.validate(finding.artifact).valid === true`.
2. يُمنع أن يمر GATE_2 بمجرد وجود locator نصي (`endpoint || file || parameter`) — هذا
   النمط القديم (`seven-gate-validator.js:31` عند 085a9c7) هو مصدر الفشل A03.
3. التحقق يجري داخل `evaluateFinding` عبر قارئ يُحقن في الـ validator (constructor
   option `artifactReader`)؛ لا يُقبل ناتج قراءة مُمرَّر من الكاشف.
4. تفاصيل أسباب الرفض تظهر ضمن `failedGates` للبوابة — لغرض التشخيص لا للالتفاف.

## §6 — الشهادة (NexaEvidenceBridge.certifyFinding)

### §6.1 — شروط الإصدار (كلها إلزامية؛ أي إخفاق = Rejection)

```js
certifyFinding(finding, target = 'local', options = {}) → Receipt | Rejection
```

1. `finding` كائن فعلي.
2. `finding.artifact` يجتاز قارئ الجسر (يملك الجسر قارئه الخاص — يُعاد التحقق ولا يُقبل
   حقل صلاحية مرفق من أي طرف).
3. **إعادة تقييم مستقلة**: الجسر يعيد تقييم الـ finding عبر validator مستقل (option
   `validator`؛ افتراضيًا `SevenGateValidator`) بسياق `options.gateContext ?? { inScope: true }`
   (تظل سياسة النطاق المستقلة فجوةً مستقلة D1.5 — لا تعالَج هنا).
4. شرط القبول: نتيجة إعادة التقييم `isValid === true` **و** `score === '7/7'` **و**
   `checks` السبع محسوبة وكل واحدة `pass === true` (قاعدة 7/7 — §10.10).
5. عند الإخفاق: إرجاع `{ certified: false, code: 'NEXA-E-REJECTED', reasons: [...],
   gateScore: <الفعلي أو null>, verified: false }` — **بلا توقيع** (§10.9).
6. أي استثناء أثناء المسار يُحوَّل إلى Rejection معلَّل — لا انتشار استثناء ولا توقيع
   احتياطي (§10.9).

### §6.2 — صدق حقول الإيصال

| الحقل | القاعدة |
|:---|:---|
| `findingId` | مشتق حتميًا من الـ digest (§6.3) — لا `Date.now()` |
| `findingDigest` | sha256 للحمولة القانونية (§6.3) |
| `artifactDigest` | sha256 للـ artifact المنقّح الذي اجتاز القارئ — يربط الإيصال بدليله |
| `gateScore` | من إعادة التقييم الفعلية فقط؛ `'7/7_PASSED'` لا تُكتب إلا بعد §6.1(4) |
| `verified` | `true` فقط في إيصال صدر بعد استيفاء §6.1؛ في الرفض `false` دائمًا |
| `certifierPublicKey` / `signature` | كما هي (Ed25519) |

### §6.3 — الحتمية وربط الحمولة

1. **الحمولة القانونية للـ digest**: `sha256(canonicalJSON({ title, severity, target, payload }))`
   حيث `payload` هو الـ finding **منقّى**: تُحذف `receipt` و`gateCheck` وكل الحقول اللحظية
   المحقونة (لا يُحقن `timestamp` عند غيابه؛ يُدرج فقط إذا كان أصلًا من الكاشف).
2. **canonicalJSON**: مفاتيح مرتبة (`sorted keys`) وبدون فراغات — نفس المدخلات ⇒ نفس السلسلة.
3. `findingId = 'NEXA-EVID-' + digest.slice(0, 16)` — حتمي.
4. **الربط**: `verifyReceipt(receipt, finding?)` — عند تقديم `finding` تُعاد حساب الحمولة
   القانونية (بنفس `target`) ويجب أن تطابق `receipt.findingDigest` **قبل** فحص التوقيع؛
   عدم التطابق = رفض فوري. بدون `finding` يبقى السلوك القديم (فحص التوقيع فقط).

## §7 — قواعد الاستقلالية (الهيكلية)

1. `ArtifactReader` لا يستورد كواشف ولا `SevenGateValidator` ولا `NexaEvidenceBridge`.
2. الكواشف لا تستورد القارئ — تنتج artifacts ولا تحكم على صلاحيتها.
3. الـ validator يستدعي القارئ عبر حقنة (`options.artifactReader`) ولا يفترض نتيجته.
4. الجسر يملك قارئه وvalidatorه ويعيد التقييم (§6.1) ولا يثق بأي `gateCheck` مرفق.
5. لا مكوّن يوقّع إلا الجسر؛ ولا مكوّن يقيّم البوابات داخل مسار التوقيع إلا بإعادة تقييم
   مستقلة.

## §8 — تصنيف أخطاء القارئ (كلها رفض، لا صمت)

| الرمز | المعنى |
|:---|:---|
| AR-E00 | استثناء غير متوقع أثناء القراءة/التحقق (fail-closed) |
| AR-E01 | الـ artifact غائب أو ليس كائنًا مفردًا |
| AR-E02 | `kind` غائب/غير نص/غير معروف |
| AR-E03 | `locator` غائب/غير نص/فارغ/فراغات |
| AR-E04 | `evidence` غائب/فارغ (نص فراغي أو كائن بلا بيانات) |
| AR-E05 | `producedBy` غائب/غير نص |
| AR-E06 | حقل حكم ذاتي داخل الـ artifact (مرفوض مبدئيًا) |

## §9 — التوافقية الخلفية

1. التواقيع العامة باقية بأسمائها: `evaluateFinding`, `filterValidFindings`,
   `certifyFinding`, `signFinding`, `verifyReceipt`, `scanSurface`, `runFullLoop`.
2. تغيّر سلوك وحيد مقصود: `certifyFinding` من «توقيع دائم» إلى «fail-closed وفق §6.1» —
   موثق في تذكرة D1.2 وتحديث كتلة الاختبار المقابلة في `tests/agentic-hunter.test.js`
   جزء من التذكرة نفسها.
3. إضافات غير كاسرة: `evaluateFinding` يضيف حقل `checks` (المساند السبعة المحسوبة)؛
   `scanSurface` يضيف `artifact` لنتائجه؛ `verifyReceipt` يقبل وسيطًا ثانيًا اختياريًا.
4. `signFinding` يبقى ممررًا إلى `certifyFinding` — أي يخضع لنفس الصرامة (A10 يُغلق بذلك).

## §10 — التعديلات الختامية (v0.3)

### §10.9 — التعديل الختامي 1: fail-closed في كل مسار القراءة والتحقق

كل مسار قراءة/تحقق في القارئ والجسر يفشل **مغلقًا**: الغياب رفض، والبنية المعطوبة رفض،
والاستثناء رفض معلَّل (AR-E00 / NEXA-E-REJECTED)، ولا `catch` يبتلع بلا أثر، ولا
default-pass بأي حال، ولا يصدر توقيع «احتياطي». الاختبارات تُثبت **وقوع الرفض المعلَّل**
لا مجرد غياب التوقيع.

### §10.10 — التعديل الختامي 2: قاعدة 7/7

1. لا إيصال إلا إذا اجتازت البوابات السبع، كلٌّ بمسندها المحسوب.
2. بوابة بقرار ثابت (`pass: true` حرفيًا — A02) أو مسند مكرر (انهيار GATE_3/GATE_6 — A09)
   تُعد **غير محسوبة**؛ إغلاق هذين النمطين فجوات مستقلة (D1.3/D1.4) لا يعفي الجسر من
   إعادة التقييم عبر الـ validator الرسمي حتى إغلاقهما.
3. `'7/7_PASSED'` قيمة مشروطة بإعادة التقييم داخل الجسر (§6.1) — كتابتها الحرفية بلا
   تحقق مخالفة تعاقدية (A01).
